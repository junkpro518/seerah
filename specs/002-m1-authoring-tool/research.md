# Phase 0 — Research: م١ أداة الإدخال/المحرّر

> قرارات تقنية تحلّ مجاهيل Technical Context. كلها تحترم القيد الأعلى: **لا تغيير على مخطط م٠**.

## R1 — المصادقة والجلسة (Next.js ↔ Supabase)

- **القرار:** `@supabase/ssr` لجلسة قائمة على الكوكيز عبر الخادم والعميل. عمليات المستخدم بمفتاح **anon** + جلسة المستخدم (RLS يفرض الصلاحيات). Server Components تقرأ بجلسة المستخدم؛ المحرّر التفاعلي Client Component.
- **الرشد:** هو النمط الرسمي لـ Supabase مع App Router؛ يبقي RLS هو الحارس الفعلي ولا يثق بالعميل.
- **بدائل مرفوضة:** استدعاء قاعدة البيانات من العميل مباشرة بلا طبقة خادم (أصعب في حماية service role وفي SSR)؛ NextAuth (يكرّر ما توفّره Supabase Auth).

## R2 — 2FA (TOTP) + الرموز الاحتياطية + إعادة التعيين

- **القرار:** Supabase Auth **MFA (TOTP)**: `mfa.enroll()` (يولّد السرّ/QR) → `mfa.challenge()`+`mfa.verify()` → الجلسة تبلغ **AAL2**. الواجهة تُلزم بلوغ aal2 قبل أي مسار `(admin)`.
- **الرموز الاحتياطية (قرار clarify):** Supabase لا يوفّرها أصلًا لـ TOTP. **تُولَّد عند التسجيل، تُعرض مرة، وتُخزَّن مجزّأة (hash) في `auth.users.app_metadata`** عبر admin API في الخادم. عند الاستعادة: يُتحقّق من الرمز (server action) → يُحذف عامل TOTP (admin) → يُعاد التسجيل. **بيانات في عمود metadata قائم — لا DDL، فـ SC-009 سليم.**
- **إعادة التعيين بيد المدير (قرار clarify):** المدير يحذف عامل MFA للعضو عبر admin API (خادم، service role) فيُعيد العضو التسجيل.
- **الرشد:** يحقّق قراري الاستعادة معًا دون لمس مخطط م٠.
- **⚠️ نقطة تأكيد للمالك:** إن فضّل المالك جدول `mfa_recovery_codes` مخصّصًا (أوضح فصلًا) بدل app_metadata، فهو **ترحيل منفصل في مسار م٠ بإذنه** — لا يُنفَّذ في م١ بلا قرار.
- **بدائل مرفوضة:** جدول رموز جديد في public (يخالف SC-009 بلا إذن)؛ الاكتفاء بإعادة تعيين المدير فقط (يخالف قرار "رموز احتياطية").

## R3 — حماية المفتاح السري (service role)

- **القرار:** `SUPABASE_SERVICE_ROLE_KEY` متغيّر بيئة **على الخادم فقط** (Coolify)، يُستخدم حصرًا في `lib/supabase/admin.ts` داخل server actions/route handlers لعمليات الإدارة المحدودة (إعادة تعيين 2FA، إنشاء حسابات). **ممنوع استيراده في أي Client Component.** يُتحقّق آليًا (فحص الحزمة + قاعدة lint) أن المفتاح لا يدخل حزمة المتصفح (SC-008).
- **الرشد:** service role يتجاوز RLS؛ تسريبه = اختراق كامل. الفصل الصارم خادم/عميل ضروري.

## R4 — المحرّر الغني (TipTap) وعقدة claim_ref

- **القرار:** TipTap (على ProseMirror). عقدة **inline مخصّصة `claimRef`** بسمة `claim_id` (uuid)، تُسلسَل ضمن `body jsonb` القائم في `*_translations` (متوافق مع تصميم م٠ §6.1). الترقيم `[n]` **يُشتق وقت العرض** بترتيب ظهور عُقَد `claimRef` في الوثيقة لكل لغة (لا تخزين أرقام). الهايلايت الملوّن من ألوان القوائم المرجعية (doc_grades/claim_types color) عبر decorations.
- **الرشد:** بنية م٠ (body jsonb حرّ + claims مشتركة) صُمّمت لهذا تحديدًا؛ لا حاجة مخطط. الاشتقاق وقت العرض يحقّق "لغتان → ترقيمان" بلا ازدواج بيانات.
- **بدائل مرفوضة:** تخزين الأرقام (يكسر تعدد اللغات ويخالف م٠)؛ جدول إشارات منفصل (يخالف SC-009).

## R5 — القفل التفاؤلي (كشف التعارض)

- **القرار:** استخدام عمود **`updated_at` القائم** (يضبطه trigger م٠). العميل يحمل `updated_at` عند الفتح؛ الحفظ: `UPDATE ... WHERE id = $1 AND updated_at = $loaded`. إن تأثّر صفر صفوف → تعارض → تحذير وإعادة تحميل، لا كتابة فوق الأحدث.
- **الرشد:** يحقّق FR-030 بلا أي تغيير مخطط (يعيد استخدام updated_at). مناسب لفريق صغير.
- **بدائل مرفوضة:** عمود `version` جديد (يخالف SC-009)؛ قفل صريح (يعطّل التوازي ويحتاج إدارة أقفال عالقة).

## R6 — بيئة التشغيل والاختبار

- **القرار:** الاستضافة على **VPS (Contabo) عبر Coolify/Dokploy** (لبنة ١٣). **الاختبار:** Vitest + RTL للوحدة؛ **Playwright E2E** للمسارات الحرجة (دخول/2FA/تحرير معلومة/انتقال مراجعة) تعمل على **مكدّس Supabase محلي زائل** (`supabase start` + ترحيلات م٠) — **لا تمسّ السحابي** (مبدأ VI: السحابي لا يُصفَّر).
- **الرشد:** يطابق قرار clarify؛ E2E محليًا يتجنّب تلويث/تصفير الإنتاج.
- **بدائل مرفوضة:** Vercel (يخرج عن قرار VPS)؛ E2E ضد السحابي (خطر على بيانات الإنتاج).

## R7 — RTL والعربية

- **القرار:** `dir="rtl" lang="ar"` على الجذر، وTailwind بخصائص منطقية (logical properties) + إضافة RTL عند اللزوم. البنية متعددة اللغات: المحرّر يعمل على سرد لغة محدّدة (العربية أصلًا في م١).
- **الرشد:** عربي أصل (لبنة ١٣)؛ الخصائص المنطقية تبسّط دعم الاتجاهين مستقبلًا.
