# موجز التسليم — للمحادثة التنفيذية

> هذه الوثيقة تُسلَّم للمحادثة التنفيذية (محادثة منفصلة). محادثة التصور انتهت؛ هنا كل ما يلزم لبدء التنفيذ.

## 0) قبل أي شيء
**اقرأ `docs/CONCEPT.md` كاملًا** — هو **مصدر الحقيقة** (٤٣ لبنة معتمدة + مراجعة Notion). ثم **`docs/GAPS.md`** (تحليل الثغرات: استراتيجي + ما يمسّ المخطط + سياسات تحريرية + تشغيلي — أغلبها محسوم، والباقي مؤجّل بوعي). كل قرار هنا مختصر؛ التفصيل هناك.

## 1) ما هو المشروع
موسوعة معرفية موثّقة للسيرة النبوية وكل شخص قابل النبي ﷺ. غير ربحية، إدخال يدوي، كل معلومة لها مرجع، تمرّ بطبقات مراجعة إلزامية. متعددة اللغات (العربية أصل). الأحداث عمود فقري، الأشخاص ملفات تتفرّع منها.

## 2) المبادئ التي يجب ألا تُكسر
- **ننقل فقط** — لا حكم على حديث من عندنا؛ يُنقل عن جهة مسمّاة؛ ولا حكم بلا `grading_source` (لبنة ٣، ١١).
- **لا اعتماد على مصدر واحد** (لبنة ١٧).
- **بوابة المراجعة إلزامية للجميع** — حتى المدير لا يقفز للنشر (لبنة ١٥، ١٩).
- **تدقيق شامل** — كل تغيير يُسجَّل حتى تشكيل حرف، + دخول/خروج الإداريين (لبنة ٢٥).
- **متعدد اللغات من التصميم** — هيكل + طبقات نصوص لكل لغة (لبنة ٢٩).
- **الترخيص:** CC BY-NC-ND، الترجمة بإذن (لبنة ٢٨).
- **لكل معلومة مفردة** مصدرها ودرجتها (لبنة ٦، ١٠)؛ والربط الذكي بالنص في م١ (لبنة ١٩).

## 3) الستاك والبيئة (لبنة ١٣، ٢٠)
- **قاعدة البيانات:** Supabase سحابي — **مشروع فارغ على حساب Supabase ثانٍ** (غير الحساب الموصول حاليًا بأدوات MCP، org `junkpro518`). تُبنى **مباشرة على السحابي** (لا Docker محلي).
- **الواجهة (لاحقًا م١+):** Next.js + Tailwind، RTL. **الاستضافة:** VPS Contabo عبر Coolify/Dokploy.
- **متوفّر على الجهاز:** Node 22، Supabase CLI 2.75، Git، Docker (مثبّت، غير مشغّل).

### الاتصال بمشروع Supabase الثاني
الأدوات المربوطة (MCP) تشير للحساب الخطأ. استخدم **Supabase CLI**:
1. `supabase login` (متصفح → اختر الحساب الثاني). **يحتاج تفاعل المستخدم.**
2. `supabase link --project-ref <REF>` — اطلب من المستخدم معرّف المشروع (من Settings → General → Reference ID).
3. الترحيلات في Git → تُطبَّق بـ `supabase db push`.

## 4) سير البناء والتزامن (لبنة ٢٠)
**مجلد محلي → GitHub → دفع للسيرفر.** زامن GitHub مع **كل مرحلة/تعديل** (commits متكررة). الترحيلات في Git = مصدر الحقيقة.

## 4.5) القالب الأساسي ومنهجية Spec Kit (إلزامي)
المشروع يُبنى على قالب المالك: **GitHub Spec Kit** — https://github.com/junkpro518/Project_template.git
- منهجية "المواصفات أولًا": `constitution → specify → clarify → plan → tasks → implement`. **لا كود بدون spec.**
- يثبّت في المشروع، وتُحدَّث أداة Spec Kit أولًا (`specify self upgrade`)، ويُتحقّق من تثبيتها قبل البدء.
- `CLAUDE.md`/`AGENTS.md` في القالب تُدمج مع تعليمات المشروع وتبقى متزامنة.
- **وثائقنا تبقى مصدر القرارات** (CONCEPT/GAPS)، و Spec Kit يُولّد مخرجاته **منها**:
  - مبادئ CONCEPT → **constitution** (دستور المشروع).
  - نطاق م٠ + GAPS → أول **spec** → plan → tasks → implement.
- **مهم:** غذِّ مرحلتي clarify/plan بقراراتنا الـ٤٣ — لا تُعِد طرحها من الصفر.

## 5) أول الخطوات للتنفيذ
1. اقرأ `CONCEPT.md` + `GAPS.md`.
2. ثبّت قالب Spec Kit في المشروع (الريبو أعلاه) + `specify self upgrade` + تحقّق من التثبيت.
3. **املأ الدستور** (`.specify/memory/constitution.md`) من مبادئ CONCEPT (ننقل فقط، بوابة مراجعة إلزامية، تعدد لغات، CC BY-NC-ND، تدقيق شامل، لكل معلومة مرجع...).
4. **اكتب spec م٠** عبر `speckit.specify` مغذّى بنطاق م٠ (القسم ٦) وقرارات ٣٣–٤٣، ثم clarify → plan → tasks. اعرض على المالك قبل implement.
5. تهيئة: مستودع GitHub → `supabase init` → ربط مشروع Supabase الثاني (CLI) → دفع الترحيلات.
6. نفّذ م٠ بـ TDD (pgTAP)، وزامن GitHub كل خطوة.

> الخطة القديمة `docs/superpowers/plans/2026-06-18-m0-database-core.md` = **مرجع أنماط فقط** (SQL/RLS/آلة الحالات)، قبل تعدد اللغات والتدقيق — لا تُنفَّذ حرفيًا.

## 6) نطاق م٠ (الكيانات والتفاصيل المحدّثة)
**الكيانات:** events · persons · locations · sources · citations · claims · claim_citations · event_persons · event_locations · profiles · content_notes · audit_log.

**تفاصيل أقرّتها لبنات ٣٣–٤٣ (يجب أن تشملها خطة م٠ الجديدة):**
- **متعدد اللغات** (لبنة ٢٩، ٣٣): طبقة هيكل + جداول نصوص/ترجمة لكل كيان نصّي، slug ومراجعة لكل لغة. **المعلومة = حقيقة مشتركة** (مصدر/درجة مرة واحدة) + نص/إشارات/ترقيم لكل لغة. عرض الترجمة الناقصة = رجوع للأصل العربي بتنبيه (لبنة ٣٤).
- **events:** `timeline_order` يدوي + سنة تقريبية موقّعة (لبنة ٣٥).
- **claims:** أعمدة ربط منفصلة (event/person/location) + قيد "واحد فقط"؛ **حذف ناعم** عبر كل الجداول؛ عمود `body_plain` للبحث (لبنة ٣٦).
- **citations:** قيد "حكم ⇐ مصدر حكم" (لبنة ٣، ٣٨).
- **review state-machine:** مفروضة للجميع (trigger) + RLS؛ anon يرى `published` فقط؛ شارة المراجعة تعكس مراجعة فعلية (R2).
- **audit_log:** كل شيء عند كل حفظ + أحداث الدخول/الخروج؛ + خطّاف **تصدير أسبوعي إلى NAS** ونسخ احتياطي خارجي (لبنة ٢٥، ٤٣).
- **profiles/أدوار:** author/shariah_reviewer/editor/admin + **2FA إلزامي** + دعوة/تعيين الأعضاء (لبنة ٤، ٤١).
- **خطّاف إشعارات تيليجرام** من سجل التدقيق (لبنة ٢٦).
- القرآن: نص مجمع الملك فهد (لبنة ٣٨).

**خارج م٠:** المحرّر الذكي والهايلايت (م١)، صفحات العرض والنمطان (م٣+/م٦)، hadiths/verses/tags/media، الخرائط، البحث (م١٣).

## 7) ما سيُطلب من المستخدم أثناء التنفيذ
- إنشاء/ربط مستودع GitHub (مصادقة).
- `supabase login` للحساب الثاني + معرّف المشروع.
- لاحقًا: توكن بوت تيليجرام + chat id؛ اسم المشروع (مؤجّل)؛ اللغة الثانية.
